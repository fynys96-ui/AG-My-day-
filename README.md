# ارتقِ كل يوم — V6 (حسابات اسم مستخدم + كلمة مرور)

## مهم قبل النشر
- V6 تحتوي على الواجهة والخادم، لكن **الحسابات لن تعمل قبل نشر الخادم** وربطه بقاعدة بيانات D1. GitHub Pages لا يشغل Backend.
- خذ نسخة احتياطية من V5 أولًا. التطبيق يحتفظ بمفاتيح V5 للضيف، ويعزل حسابات المستخدمين بمفاتيح خاصة لكل حساب محليًا وبـ user_id على الخادم.
- لا توجد استعادة كلمة مرور بالبريد؛ إن فقدت كلمة المرور فلا توجد آلية استعادة تلقائية. أضف استردادًا إداريًا آمنًا قبل الإطلاق الواسع.

## تشغيل Backend على Cloudflare
1. أنشئ حساب Cloudflare (مالك التطبيق فقط؛ المستخدمون لا يحتاجون حساب Cloudflare).
2. ثبّت Node.js على جهازك، ثم نفّذ في مجلد `backend`:
   `npm install -g wrangler`
   `wrangler login`
   `wrangler d1 create irtaqi-users`
3. انسخ `database_id` الناتج إلى `backend/wrangler.toml` بدل `REPLACE_WITH_YOUR_D1_DATABASE_ID`.
4. نفّذ: `wrangler d1 execute irtaqi-users --remote --file=schema.sql`
5. نفّذ: `wrangler deploy`
6. انسخ رابط Worker الذي يظهر بعد النشر، وافتح تطبيق V6 ثم **الإعدادات ← حسابي والمزامنة ← عنوان خادم الحسابات**، واحفظ الرابط.
7. لتسهيل استخدام الزوار، ضع رابط Worker في ثابت `v6DefaultApi` في `index.html` (أو غيّر دالة `v6Url` لتستخدم رابطك الافتراضي) ثم انشر تحديث الواجهة على GitHub Pages.

## ملفات GitHub Pages
ارفع إلى جذر المستودع: `index.html`, `manifest.webmanifest`, `sw.js`, `icon-192.png`, `icon-512.png` فقط. **لا ترفع مجلد backend إلى جذر الموقع باعتباره خادمًا؛ هو كود تنشره منفصلًا على Cloudflare.**

## العزل والأمان
- الحسابات تستخدم اسم مستخدم `[a-z0-9_]` بطول 3–24 حرفًا وكلمة مرور لا تقل عن 12 حرفًا.
- كلمات المرور محفوظة كـ PBKDF2-SHA256 (310,000 دورة) مع salt فريد، ولا تُحفظ نصًا صريحًا.
- جلسات الدخول تعتمد على رموز عشوائية قوية، ويُحفظ hash الرمز في قاعدة البيانات. رموز الجلسة محفوظة محليًا في المتصفح، لذا يجب تجنب إدخال سكربتات غير موثوقة في الواجهة (XSS).
- جميع طلبات البيانات مرتبطة بـ user_id المستخرج من جلسة موثقة **على الخادم**، وليس من قيمة يرسلها العميل.
- يوجد حد أساسي لمحاولات الدخول وتحقق من مصدر الواجهة (CORS). قبل النشر الكبير أضف Cloudflare WAF / Turnstile ونسخ D1 احتياطية.
- المزامنة تعتمد على revision لاكتشاف تعارضات الجهازين؛ عند التعارض لا يتم الكتابة فوق نسخة الجهاز الآخر تلقائيًا.
- لا يوجد تشفير طرفي للبيانات؛ مشغّل الخادم يستطيع نظريًا قراءة البيانات المخزنة. اذكر ذلك في سياسة الخصوصية.
- حذف الحساب واسترداد كلمة المرور وسياسة الخصوصية وشروط الاستخدام وإدارة إساءة الاستخدام ليست مكتملة بعد، وهي مطلوبة قبل الإطلاق العام الكبير.

## ترحيل بياناتك
- سجل حسابًا جديدًا. **لن يتم رفع بيانات ضيفك تلقائيًا**.
- افتح الإعدادات واضغط «نقل بيانات ضيفي لهذا الحساب» بعد التأكد من أن لديك نسخة احتياطية.
- أي مستخدم جديد يحصل على ملف مستقل وفارغ من تقدمك.
